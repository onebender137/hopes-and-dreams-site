Expose Ollama to WSL Over the Network

The connection between Ollama running on Windows and WSL (Windows Subsystem for Linux) can be tricky due to network interface issues and VRAM constraints. Here’s how you can set it up correctly, ensuring that you own your stack and don't fall into common pitfalls.

THE PROBLEM

Connecting Ollama on Windows to a WSL instance running Ubuntu can result in several errors, including RemoteDisconnected, "Connection refused," and 300 errors ("llama runner process has terminated"). These issues stem from incorrect IP detection logic and insufficient VRAM for large models like phi4.

THE STACK

Hardware & Software Requirements

  • Hardware: Windows machine with sufficient VRAM (9GB+ for phi4 model).
  • Software:
  • Ollama installed on the Windows host.
  • WSL2 Ubuntu instance.
  • Bridged/mirrored network mode in WSL.

Prerequisites

  1. Ensure Ollama is running on your Windows machine and has a recent release with necessary fixes.
  2. Install WSL2 with an Ubuntu distribution.

THE BUILD

Follow these steps to expose Ollama to WSL over the network:

Set Environment Variable in Windows

Ensure that Ollama listens on all interfaces by setting OLLAMA_HOST=0.0.0.0 in your Windows environment variables before starting Ollama.

setx OLLAMA_HOST "0.0.0.0"

Detect the Correct IP Address

In WSL, use the following command to find the actual default gateway (Windows host IP):

ip route show default | awk '/default/ {print $3}'

Alternatively, enable mirrored networking by adding an entry in .wslconfig:

[wsl2]
localhostNetworkAddress=127.0.0.1

Add IP Detection Function

Add a _get_wsl_host_ip() function to detect and use the actual Windows host IP from /etc/resolv.conf or routing table if WSL was in bridged/mirrored network mode:

def _get_wsl_host_ip():
    with open('/etc/resolv.conf', 'r') as f:
        for line in f.readlines():
            if line.startswith('nameserver'):
                return line.split()[1]

Set Environment Variable

Set the environment variable OLLAMA_HOST=127.0.0.1:11434:

export OLLAMA_HOST="127.0.0.1:11434"

Use the following curl command in WSL to test connectivity:

curl -s http://127.0.0.1:11434/api/chat -d '{"model":"phi4:latest","messages":[{"role":"user","content":"say hi"}],"stream":false}'

Monitor VRAM Usage

Ensure that your system has sufficient VRAM before running large models like phi4, as the model requires approximately 9GB of VRAM.

THE GOTCHAS

  • IP Detection Logic: Incorrect IP detection logic can lead to WSL attempting to connect using 127.0.0.1, which may not route correctly.
  • VRAM Constraints: The phi4 model requires significant VRAM and can cause Ollama to crash if other processes are consuming VRAM.
  • Environment Variables: Set environment variables such as OLLAMA_HOST properly to ensure connectivity.
